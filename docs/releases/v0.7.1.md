## research-mcp v0.7.1

An MCP server for academic literature research. Combines Scopus search with free,
open scholarly APIs so you get abstracts, author metrics and open-access PDFs
without needing institutional Scopus entitlements.

Two headline changes: Scopus searches now report their **total hit count** and
can page beyond 25 results, and whole result sets can be **exported to a file**.

### Total hit counts and paging

`search_scopus` now returns an object instead of a bare list. Every response
carries what a PRISMA-S search log needs per query:

- `total_results` — the hit count for the whole query, from Scopus's
  `opensearch:totalResults` (it was never read before)
- `query` as sent, `retrieved_at` (local time with UTC offset) and `mcp_version`
- `returned`, `start`, `next_start` for paging, and `quota_remaining`

New parameters: `start` (0-based offset), `count_only` (the hit count in one
request, no records — for counting hits across many search strings), `compact`,
and `count` up to 200. Above 25 the server pages through Scopus (25 per request)
and returns compact records so a large page stays readable.

Zero hits now give `total_results: 0` and an empty list. Scopus answers an
empty result set with a pseudo-entry (`"error": "Result set was empty"`), which
used to surface as a record with every field blank.

The OpenAlex citation tools page as well: `get_citing_papers` takes `page` and
reports `next_page`; `get_references` takes `start`, ranks a window of at least
50 references by citations and reports `next_start`. Both accept `count` up to
100. `assess_relevance` is unchanged (25 papers per call).

### Export to file

New tool **`export_scopus_results(query, filename)`** pages through a result set
of up to 2000 hits (80 Scopus requests) and writes it as CSV (semicolon-separated,
Excel-ready) or JSON into the folder set by `RESEARCH_EXPORT_DIR` — the
**Export folder** the `.mcpb` install dialog now asks for. A `<name>.meta.json`
with query, hit count, retrieval time and server version sits beside the data.
The response carries the hit count and the paths, never the records, so the
conversation stays small.

### Cowork plugin and configuration file

Releases now also ship **`research-mcp-vX.Y.Z-plugin.zip`**, a Claude Cowork
plugin for sessions that run on your own computer: upload it under
Customize → Plugins → Add → Upload plugin. Its start command is a shell
one-liner that installs uv if missing and runs
`uvx --from <GitHub archive of v0.7.1> research-mcp`, so nothing has to be
installed by hand (Cowork runs plugin servers on Linux, on Windows inside the
app's VM). Settings come from a local file, because plugins have no settings
dialog and must not carry secrets. `scripts/diagnose-plugin.ps1` checks the
config file and the start command outside the app.

That file is new for every install method: `~/.research-mcp/config.json`
(`%USERPROFILE%\.research-mcp\config.json` on Windows) with `scopus_api_key`,
`unpaywall_email` and `export_dir`. Environment variables still take precedence,
so existing configs keep working unchanged. See `config.example.json`.

### Tools
- `search_scopus` — search Scopus by query; **now with total hit count, paging and `count_only`**
- **`export_scopus_results`** — write a whole result set to CSV/JSON *(new)*
- `get_abstract_details` — Scopus metadata + abstract text via CrossRef
- `get_author_profile` — h-index, citations, ORCID, affiliations via OpenAlex
- `get_citing_papers` — forward citations, now paged
- `get_references` — backward citations, now paged
- `assess_relevance` — screen papers against a research context
- `get_pdf_link` — open-access PDF via Unpaywall
- `get_journal_metrics` — journal quartile, CiteScore, SJR, SNIP
- `get_quota_status` — live Scopus rate-limit

### Breaking change
`search_scopus` (and `get_citing_papers` with `source="scopus"`) returns an
object with a `results` list instead of a bare list. Anything that indexed the
response directly needs to read `response["results"]`.

### Also in this release
- **Export folder resolution is defensive.** The folder comes from the
  environment, then `~/.research-mcp/config.json`, then `research-mcp` in the
  home directory, and the first one that can actually be created wins. Claude
  Desktop resolved the manifest's `${DOCUMENTS}` default to a folder that
  cannot exist (`C:\Users\.<name>\Documents`), which used to block every
  export; the manifest no longer sets that default and the response reports
  `export_dir_source`.
- The `.mcpb` bundle starts uv with `--python-preference system`: a Python
  ≥ 3.10 already on the machine is reused, and a managed one is downloaded only
  when none qualifies. The server logs which interpreter it runs on.
- An empty `UNPAYWALL_EMAIL` (as a config dialog may pass it) falls back to the
  default instead of sending an empty `mailto:`.
- `tests/test_manifest.py` keeps `manifest.json` in step with `pyproject.toml`
  and the served tools; CI validates the manifest and does a trial pack.
- The release workflow checks out the tagged commit before the version check and
  the bundle build.
- **110 offline unit tests** (up from 77), CI on Python 3.10–3.13.

### Install
Download `research-mcp-v0.7.1.mcpb` below and double-click it. To pin the source
instead:

```json
{
  "mcpServers": {
    "research": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/niol-zh/research-mcp@v0.7.1", "research-mcp"],
      "env": {
        "SCOPUS_API_KEY": "your-key",
        "UNPAYWALL_EMAIL": "you@example.com",
        "RESEARCH_EXPORT_DIR": "/path/to/your/literature/folder"
      }
    }
  }
}
```

Only dependencies: `mcp` and `httpx`. MIT licensed.
